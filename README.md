# Онлайн-бронирование столика в ресторане

Асинхронный бэкенд-сервис на FastAPI для управления бронированиями столов в ресторанах. Проект полностью контейнеризирован и подготовлен к production-разработке.

## Архитектура и технические решения

1. **Асинхронный стек повышенной производительности**: Сервис написан на Python 3 (Asyncio) с использованием **FastAPI**, **SQLAlchemy 2.0** и асинхронного драйвера **asyncpg** для работы с СУБД. Это обеспечивает максимальную пропускную способность без блокировки потоков.
2. **Контейнеризация и инфраструктура**: Настроен многоконтейнерный стек через **Docker-Compose**. Локальное окружение разработки полностью изолировано от боевой среды. Базы данных используют Docker Volumes для сохранения данных при перезапусках.
3. **Изолированная среда тестирования**: В архитектуру заложены две независимые базы данных **PostgreSQL 15** (одна для разработки, вторая — чистая база для прогона автотестов).
4. **Глубокое покрытие автотестами**: Бизнес-логика защиты слотов покрыта параметризованными интеграционными тестами на **Pytest** (с использованием `httpx.AsyncClient`).
5. **Надежная валидация (Pydantic v2)**: Проверка корректности данных (формат номеров телефона, лимиты гостей, часовые слоты с 12:00 до 22:00) вынесена на уровень схем с использованием `@field_validator`, отсекая некорректные запросы до обращения к БД.
6. **Мягкое удаление (Soft Delete)**: Эндпоинт удаления брони не стирает данные, а переводит их в статус `cancelled`, сохраняя историю для последующей бизнес-аналитики.
7. **Защита от овербукинга**: Внедрена проверка занятости даты и времени только среди `active` записей, что автоматически освобождает слот при отмене бронирования.

## Быстрый запуск всего стека в Docker

Для сборки образов и автоматического запуска приложения и двух баз данных PostgreSQL выполните в корне проекта:

```bash
docker-compose up --build -d
```

* После запуска интерактивная документация API (Swagger) будет доступна по адресу: **http://127.0.0**

---

## Запуск автотестов

Для прогона пула параметризованных тестов внутри изолированного контейнера выполните команду:

```bash
docker-compose exec web pytest
```

---

## Локальная разработка (Стиль Б)

Если вы хотите запускать код локально из IDE, используйте Docker только для поднятия инфраструктуры баз данных:

1. Запуск баз: `docker-compose up -d postgres_db postgres_test_db`
2. Переменные окружения автоматически подтягиваются из файла `.env` через `python-dotenv`.
